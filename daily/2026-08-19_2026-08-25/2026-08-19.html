摘要

今天分兩條線。前半天建立一套統一的 Claude Code 技能架構並讓每日進度可以自動歸檔；後半天把工作環境延伸到實驗室伺服器，開始用它檢視既有的方法文件。

整合了八個來源的 skill。判定它們分屬不同抽象層級 — 有的是永遠生效的行為約束、有的是外部服務、有的是按需觸發的工作流、有一份根本是教材而非 skill — 平鋪合併會造成 context 爆炸與觸發衝突，因此重新設計為分層模型，並以 bucket + promotion 機制作為 context 預算閘門。共 37 個 skill 完成安裝與交叉相依驗證。

自建三個 skill：daily-progress-report（每日進度歸檔）、weekly-progress-deck（週報簡報）、delegation（subagent 委派決策框架）。

進度歸檔採白名單抽取：只取工作階段標題、時間與工具統計，thinking 區塊與 tool_result 內容一律不取，避免檔案內容與憑證外流。抽取後與發布前各做一次脫敏掃描。由於目標 repo 是公開的，發布前會自動偵測 remote 可見性並加套一組研究資料規則（定序檔名、樣本編號、資料庫 accession），且檔案路徑一律收斂為專案層級。當天稍晚回頭驗證了這條管線：預覽當日報告、逐項確認抽取邊界，確認以指令操作遠端的工作只會留下工具次數與時間，指令本身與回傳內容不進報告。

後半天把環境接到伺服器：完成金鑰登入、在伺服器端安裝 CLI 並授權，把 skill 與工作規範複製到新的工作目錄。接著以唯讀方式取用遠端資料，對照一份既有方法文件檢視其解法，並把結論整理成 HTML 摘要。

過程中處理的問題：

  • PowerShell 5.1 預設以 ANSI 讀取 .ps1，原始碼含中文會破壞引號結構導致無法解析。解法是腳本保持純 ASCII、人看的文案外置到 UTF-8 模板，並加自動檢查
  • PowerShell 變數名不分大小寫，累加用的變數意外覆蓋了整數參數
  • System.Globalization.ISOWeek 是 .NET Core 專屬，PowerShell 5.1 沒有。自行實作 ISO 週計算時發現跨年邊界算錯（2027-01-03 應屬 2026-W53），修正後通過 10 組邊界測試
  • git clone 撞到 Windows 260 字元路徑上限時 checkout 只完成六成，卻仍回傳 exit 0。以 core.longpaths 加 git reset --hard 補齊，並改為 clone 後核對檔案數
  • ssh-copy-id 在 Windows 沒有，公鑰佈署改走其他方式
  • 「活躍分鐘」原本把各工作階段的起訖時間直接相加，平行階段重疊計算、掛機時間也照算。改為先在超過 15 分鐘的空檔切段，再跨階段取時間聯集，並以獨立重算驗證一致

環境建置完成 GitHub CLI 授權與 Node.js 安裝，並將工作目錄遷移至外接磁碟，驗證含空格的路徑不影響腳本運作。

明天要接的：把伺服器端的資料檢視結果收斂成可複用的流程，並確認排程發布要不要開。
